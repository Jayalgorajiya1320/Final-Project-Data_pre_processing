# Customer Credit Risk Data Preprocessing Project

## Project Overview

This project demonstrates a complete data-preprocessing workflow using Python, Pandas, NumPy and Scikit-learn on a **Customer Credit Risk Dataset**. The notebook covers data acquisition, data understanding, missing-value treatment, outlier handling, feature engineering, encoding, scaling, transformations and preparation of a final dataset for machine-learning work.

The target column used for the credit-risk problem is `default_flag`:

- `0` = No Default
- `1` = Default

The project frames this as a **binary classification** problem. The notebook focuses on data preparation; it does not train or evaluate a final classification model.

## Project Workflow

### Part A — Conceptual Foundation

- Definition and steps of Data Analysis.
- Planning a Data Science project.
- Framing a Machine Learning problem.
- Explanation of tensors and NumPy examples.

### Part B — Data Acquisition

The notebook demonstrates multiple data sources:

1. **CSV:** Load the customer credit risk dataset with Pandas.
2. **JSON:** Work with customer metadata represented as JSON.
3. **SQL:** Connect to `loan_database.db` using SQLite and query `loan_repayment_history`.
4. **API:** Fetch sample user data from JSONPlaceholder using the Requests library.

For the SQL exercise, the database file and table must exist. To see available tables, run:

```python
import sqlite3
import pandas as pd

conn = sqlite3.connect("loan_database.db")

tables = pd.read_sql_query(
    "SELECT name FROM sqlite_master WHERE type='table';",
    conn
)

print(tables)
conn.close()
```

If `loan_repayment_history` is not listed, create or provide the database table before running the corresponding `SELECT` query. Connecting to SQLite creates an empty database file if it does not already exist; it does not automatically create the requested table.

The API exercise requires an internet connection.

### Part C — Data Understanding and Cleaning

- Inspect records using `head()`, `info()`, `describe()` and `shape`.
- Check missing values with `isnull().sum()`.
- Generate a data-quality report using `ydata-profiling`.
- Demonstrate missing-value methods:
  - Mean and median imputation.
  - Most-frequent category imputation.
  - Missing indicator with random-sample imputation.
  - K-Nearest Neighbors (KNN) imputation.
  - Iterative imputation (MICE-style).
  - Complete-case analysis by dropping rows or columns.

The notebook creates separate DataFrame copies for several imputation demonstrations. These are examples of alternative strategies; they are not all applied sequentially to one single final DataFrame.

### Part D — Outlier Handling

The notebook demonstrates outlier detection and treatment using:

- **Z-score:** identifies values more than three standard deviations from the mean; the example removes flagged rows.
- **IQR:** identifies values outside Q1 − 1.5 × IQR and Q3 + 1.5 × IQR; the example caps values at these bounds.
- **Percentile method:** uses the 5th and 95th percentiles; the example caps values at these limits.
- **Winsorization:** caps the lowest and highest 5% of values in the example.

### Part E — Feature Engineering

The notebook covers:

- Identifying numerical and categorical columns.
- Extracting year, month, day and weekday from `join_date`.
- Ordinal encoding for `education_level`.
- Label encoding for `gender`.
- One-hot encoding for `region` and `loan_purpose`.
- Income binning.
- Credit-score binarization using a threshold of 700.
- Quantile binning and K-Means grouping of `transaction_count`.

### Part F — Feature Scaling

Five scaling approaches are demonstrated:

1. Standardization (Z-score scaling).
2. Normalization.
3. Min-Max scaling.
4. MaxAbs scaling.
5. Robust scaling.

The notebook creates separate scaled DataFrames to compare the methods.

### Part G — Feature Construction and Transformation

Transformations demonstrated:

- Log transformation.
- Reciprocal transformation.
- Square-root transformation.
- Box-Cox transformation.
- Yeo-Johnson transformation.
- `ColumnTransformer` with separate numerical and categorical pipelines.

New or derived features:

- `debt_to_income_ratio` = `loan_amount` / `annual_income`.
- `avg_monthly_transactions` = `transaction_count` / 6.
- `spending_ratio` is already present in the source dataset and is displayed as the spending-to-income feature.

### Part H — Final Deliverables

The final section:

- Removes duplicate rows.
- Creates the debt-to-income and average monthly transaction features.
- Imputes numerical missing values using the median.
- Scales numerical features using `StandardScaler`.
- Imputes categorical missing values using the most frequent category.
- One-hot encodes categorical features.
- Preserves `customer_id` and `default_flag`.
- Saves the result as `final_cleaned_transformed_dataset.csv`.

It also includes code to create a text preprocessing summary.

## Notes and Limitations

- The notebook demonstrates several alternative preprocessing methods. The separate demonstrations should not be interpreted as one combined pipeline.
- The Part H pipeline applies median imputation and standardization to the selected numerical columns, and most-frequent imputation plus one-hot encoding to selected categorical columns. It does not automatically apply every outlier, scaling and transformation method demonstrated earlier.
- The final output retains `default_flag` as the target column. For model training, separate the target from the input features.
- For a valid machine-learning evaluation, split data into training and test sets **before** fitting imputers, encoders, scalers or other learned preprocessing steps. Fit preprocessing on training data only, then transform the test data to avoid data leakage.
- The reciprocal transformation requires non-zero values. The Box-Cox transformation requires strictly positive values. Log and square-root transformations also require values in their valid domains.
- The current final pipeline calculates `debt_to_income_ratio` as loan amount divided by annual income. Rows with zero annual income can produce an undefined or infinite value; the notebook replaces infinite values with missing values before imputation.
- `spending_ratio` is already a source column; the notebook does not derive it from a separate total-spending column.
- Actual output row and column counts depend on the supplied CSV. They are not hard-coded in this README.
